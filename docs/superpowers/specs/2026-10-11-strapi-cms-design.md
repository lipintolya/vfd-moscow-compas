# Strapi как CMS для сайта салона — решения

Дата: 2026-10-11. Согласовано с владельцем проекта в переписке.

## Цель

Директор салона сам добавляет и правит статьи, акции и работы портфолио —
без кода, без GitHub, в интерфейсе на русском. Сайт остаётся статическим
(скорость не меняется), каталог и цены — в Supabase, как сейчас.

Доступ — у двоих: разработчик (главный администратор) и директор
(редактор, публикует сам, без одобрения).

Успех:
- директор добавляет статью с фото и галереей, не видя ни одного тега;
- после переноса тексты всех страниц сайта совпадают с нынешними;
- сборка не проходит, если Strapi недоступен или запись заполнена с ошибкой
  (на сайт не уходит пустой или сломанный раздел).

## Объём

**Этап 1 (сейчас, локально):** Strapi в проекте, разделы и поля, русский
интерфейс, роли, чтение данных сайтом, перенос текущих материалов, проверка,
инструкция для директора.

**Этап 2 (когда будет VPS и домен):** Strapi и PostgreSQL на том же VPS
(`admin.<домен>`), пересборка сайта после публикации, ночная пересборка
(цены Supabase), резервные копии, ежедневная выгрузка контента.

**Не входит:** видео, отзывы, тексты страниц и контакты (остаются в коде);
каталог и цены (Supabase); предпросмотр черновика на сайте.

## Устройство

- `cms/` — проект Strapi 5 (5.57, TypeScript) со своим `package.json`.
  Устройство разделов и полей (`cms/src/api/*/content-types`,
  `cms/src/components`) — код в Git; материалы — в базе.
- База: локально SQLite (`cms/.tmp/data.db`, вне Git), на сервере PostgreSQL;
  выбор — переменными окружения, код один.
- Node.js 26 (Strapi 5.57 поддерживает 20–26). Docker не нужен.
- Команды из корня: `npm run cms` (админка, `localhost:1337`),
  `npm run dev` (сайт). Переменные сайта: `STRAPI_URL`, `STRAPI_TOKEN`
  (ключ только для чтения), в `.env`.
- Плагин i18n (многоязычный контент) выключен — контент на одном языке.

## Разделы и поля

Все разделы — с черновиками (Draft & Publish). Адреса страниц (`slug`) —
поле UID из названия (транслит), можно поправить.

**Акция** (`promo`): название*, условия*, описание, фото, действует до*
(дата), скидка (текст), кнопка — текст и ссылка. После даты окончания акция
уходит в архив (`/promo-archive/`), как сейчас. Заглушки не переносим; пока
активных акций нет, блок на главной скрыт.

**Работа портфолио** (`work`): название*, адрес*, дата*, вид* (межкомнатные /
скрытые / перегородки), объект* (квартира / дом / офис / коммерческий),
город, короткое описание* (до 160 знаков), история, особенности (список),
метки (список), модель, число дверей, фото* (несколько, первое — обложка),
ссылка на раздел каталога (выбор из списка + подпись).

**Статья** (`article`): заголовок*, адрес*, вид (статья / публикация), дата
публикации*, дата обновления, обложка* + описание фото*, лид* (до 160 знаков),
«Коротко» (2–5 пунктов), тело — блоки (dynamic zone), вопросы-ответы,
ключевые фразы. Свёрнутая группа «Для поисковиков и каталога»: свой title,
шаги (HowTo), связь с покрытиями, сериями и страницами каталога, автор (если
не основатель), показ на главной (spotlight: плашка, лид, фото, видео,
пункты).

**Блоки статьи** (компоненты): «Текст» (Rich text Blocks: подзаголовки,
списки, ссылки, жирный, цитата), «Фото» (снимок, описание, подпись, ссылка),
«Галерея» (2–4 фото, вариант «высокие двери»), «Выноска» (тип + текст),
«Видео» (ролик, обложка, название, подпись), «Таблица» (Markdown-текст —
в Blocks таблиц нет), «Цены скрытых дверей», «Цены по покрытиям» (без полей,
цены — из каталога при сборке).

**Подстановки в тексте:** `{адрес салона}`, `{цена комплекта Секрет}` и т. п.
— русские имена нынешних переменных статей (`src/lib/article-vars.ts`);
при сборке заменяются актуальными значениями, неизвестная подстановка —
ошибка сборки. Список — подсказкой у полей.

## Как сайт читает Strapi

- `src/lib/strapi.ts` — клиент REST API (ключ, постраничная загрузка,
  понятные ошибки).
- `src/content.config.ts`: коллекция `articles` — загрузчик из Strapi вместо
  `glob(*.mdoc)`; данные приводятся к нынешней схеме, поэтому
  `src/lib/articles.ts`, главная, раздел, карта сайта, `/llms.txt`,
  «статья по теме» не меняются. Тело статьи выводит новый компонент
  `ArticleBlocks.astro` из нынешних компонентов статей (Figure, Photo,
  PhotoGrid, Callout, InlineVideo, HiddenHeightPrices, CoatingPrices).
- Акции и портфолио — коллекции `promos` и `works` с загрузчиками из Strapi;
  `src/data/promos.ts` и `portfolio-works.ts` остаются как типы и подписи
  (категории, цвета), данные — из коллекций.
- Ошибки: Strapi недоступен или запись не проходит проверку схемы — сборка
  останавливается с названием записи.
- Локально правка в Strapi видна на сайте через секунды: вебхук Strapi →
  служебный адрес дев-сервера → `refreshContent`.

## Фото

- Медиатека Strapi (локальное хранилище: `cms/public/uploads`, вне Git).
  Strapi нарезает уменьшенные копии (размеры задаются в настройках); сайт
  строит `srcset` из них.
- Адрес на сайте: `/uploads/…`. Локально дев-сервер Astro проксирует
  `/uploads` на Strapi; на сервере nginx отдаёт папку с диска (сайт не
  зависит от работы Strapi).
- Перенос: фото статей и работ загружаются в медиатеку скриптом
  (с описаниями); `public/media` остаётся для остального сайта.

## Русский интерфейс и доступ

- `cms/src/admin/app.tsx`: язык `ru`, по умолчанию; недостающие строки
  Strapi (админка, редактор, медиатека) — свой словарь перевода.
- Названия разделов, полей, подсказки — по-русски (настройки отображения).
- Роли: разработчик — Super Admin; директор — Editor (создаёт, правит,
  публикует, снимает с публикации, удаляет; настройки и Content-Type
  Builder не видит).
- Публичный API закрыт; сайт читает по ключу только для чтения.

## Перенос и проверка

- Скрипт `cms/scripts/import.mjs`: 11 статей (Markdoc → блоки, переменные →
  подстановки), 3 работы, фото в медиатеку. Повторный запуск не дублирует.
- Проверка: сборка до и после, тексты всех страниц совпадают (как при чистке
  проекта), просмотр на телефоне. После — удаляются `src/content/articles/*.mdoc`
  и данные из `promos.ts`/`portfolio-works.ts` (история — в Git).
- Инструкция для директора: как добавить статью, акцию, работу (с картинками).

## Этап 2 (сервер) — заготовка

- Strapi + PostgreSQL на VPS, `admin.<домен>` через nginx, HTTPS.
- Публикация → вебхук → пересборка (несколько правок подряд — одна
  сборка), ~1–2 минуты; ночная пересборка ради цен Supabase.
- Ежедневно: копия базы, папки фото и выгрузка контента (`strapi export`) —
  замена истории правок, которой нет в бесплатном Strapi.

## Риски

- В бесплатном Strapi нет истории правок и согласования — закрываем
  ежедневной выгрузкой (этап 2) и тем, что редактор один.
- Переходы между крупными версиями Strapi ломали совместимость — версию
  фиксируем, обновляем осознанно.
- Таблицы — Markdown-текстом (в Blocks их нет); их добавляет разработчик.
