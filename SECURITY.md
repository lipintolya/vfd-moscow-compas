# Безопасность

Сайт публичный (https://dveriziz.ru), репозиторий — портфолио разработчика. Здесь описано, как устроена защита, что проверено и что осталось на совести окружения.

## Как устроена защита

- **Статический сайт.** На сервере только nginx и готовые файлы: нет приложения, базы и админки, которые можно взломать. `/admin`, `/cms/`, `.env`, `.git` отдают 404.
- **Секретов в репозитории нет.** `.env`, ключи, адрес сервера (`deploy/server.json`) и состояние деплоя — в `.gitignore`, в Git только образцы (`.env.example`, `deploy/server.example.json`). Историю коммитов проверили на токены, ключи и пароли — чисто.
- **CMS не торчит наружу.** Strapi слушает только `127.0.0.1`, работает на компьютере разработчика; сайт читает её во время сборки токеном «только чтение». В продакшене CMS нет.
- **Контент из CMS не исполняется.** Весь текст статей экранируется (`src/lib/article-blocks.ts`), ссылки проходят белый список схем (`https:`, `mailto:`, `tel:`, `/…`, `#…` — `javascript:` и `data:` останавливают сборку), JSON-LD экранирует `<`.
- **Заголовки и CSP** (`deploy/nginx/headers.conf`): HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors 'self'`, `object-src 'none'`, `base-uri 'self'`; внешние хосты — белый список (Яндекс Метрика, плееры VK и Rutube, видео из Yandex Cloud). Версия nginx не раскрывается.
- **Сервер.** Скрипт `deploy/setup-server.sh` ставит файрвол (ufw: SSH, HTTP, HTTPS), fail2ban, автообновления безопасности и HTTPS (Let's Encrypt), http и `www` перенаправляются на `https://dveriziz.ru`.
- **Деплой без инъекций.** `scripts/deploy-site.mjs` запускает `rsync` и `ssh` через `execFileSync` с массивом аргументов (без shell) и перед выкладкой проверяет сборку: карта сайта, `robots.txt`, отсутствие заглушек.
- **Персональные данные.** Яндекс Метрика грузится только после согласия на cookie (ФЗ-152), без согласия cookie не ставятся. Форм с отправкой данных на сайте нет: обращения идут в мессенджеры и по телефону.
- **Зависимости.** `npm audit` по сайту — 0 уязвимостей; Dependabot (`.github/dependabot.yml`) следит за обновлениями сайта и CMS.

## Что проверить на стороне окружения

- **Supabase (каталог).** Публичный ключ `anon` попадает только в сборку (запросы идут на этапе `npm run build`), но он по определению публичный: в панели Supabase у всех таблиц каталога должна быть включена RLS с политикой **только чтения** для роли `anon`.
- **CMS (Strapi 5.57).** `npm audit` по `cms/` показывает уязвимости в зависимостях Strapi (в основном транзитивные: DOMPurify, Handlebars и др.). Админка работает только локально и не доступна из сети; перед выносом CMS на сервер — обновить Strapi до актуальной версии, закрыть админку за VPN или базовой аутентификацией nginx и включить резервные копии.
- **CSP.** В `script-src` остаётся `'unsafe-inline'` — этого требуют встроенные скрипты запуска островов Astro/Vue и баннер cookie. Следующий шаг — nonce или хеши.
- **SSH.** Проверено 31.10.2026: сервер предлагает только вход по ключу (пароль отключён), снаружи открыты лишь порты 22, 80 и 443. Скрипт настройки сам этого не делает — держите `PasswordAuthentication no` и `PermitRootLogin prohibit-password`; ключ на рабочей машине должен быть защищён парольной фразой.
- **HSTS** выдаётся на год без `includeSubDomains` и `preload` — включать, когда все поддомены будут на HTTPS.
